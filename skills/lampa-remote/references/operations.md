# Операционный справочник Lampa Remote

Справочник соответствует CLI 0.3.1 / protocol 2.
Проверяй `--help` установленной версии, если синтаксис отличается.
Примеры используют `node dist/cli.js` из корня клона; установленный `lampa` эквивалентен.

## Установить

Предусловия: Node.js 22+, npm, ADB в PATH; TV с включённой ADB-отладкой,
авторизованным компьютером и Lampa, поддерживающей пользовательские плагины.
Компьютер с CLI должен иметь ADB-доступ к TV: удалённый агент запускает команды именно там.
Дополнительный MCP или доступ к внутренним исходникам Lampa не нужен.

1. Получи клон в каталоге задачи и собери CLI:

   ```sh
   git clone https://github.com/krajcik/lampa-remote.git
   cd lampa-remote
   npm ci
   npm run build
   node dist/cli.js --help
   ```

2. Выполни `adb devices -l`; используй подтверждённый `SERIAL` в состоянии `device`.
   Offline/unauthorized исправляй на уровне подключения/авторизации TV.
   Подключение к неизвестному адресу и выбор первого из нескольких устройств не заменяют выбор TV.
3. Запусти `node dist/cli.js start SERIAL`.
   Команда создаёт приватный конфиг, запускает мост и устанавливает ADB reverse на его порт.
   Она не открывает Lampa. `start SERIAL` не сохраняет serial в конфиге:
   при нескольких устройствах запиши нужный `serial` в `.local/config.json`.
4. Выполни `node dist/cli.js install-url`.
   JSON содержит публичную ссылку в `data.url`. Добавь её в Lampa:
   "Настройки" → "Расширения" → "Добавить плагин".
   Токен, loader и приватный файл URL не нужны. При стандартном конфиге ссылка:
   `https://krajcik.github.io/lampa-remote/plugin/remote.js?v=0.3.1#`.
   Сохраняй завершающий `#`: он удерживает добавляемые Lampa данные аккаунта вне HTTP-запроса.
   Для нестандартных port/browserWakeCode/wakeTimeoutMs команда добавляет несекретные
   параметры после `#lampa-remote=`; сохраняй ссылку целиком.
   JS загружается с GitHub Pages при старте приложения, без обращений к мосту.
   Подключение WebSocket происходит только по служебной клавише CLI.
   Голый raw.githubusercontent.com URL не используй: его MIME не подходит для script.
5. В рамках установки выполни явный `app restart`, затем `status` и `doctor`.
   Успех: свежий `status` имеет `appready: true`, версии 0.3.1/protocol 2 совпадают
   с мостом, `doctor` — `ready: true`. Готовность экрана проверь `wait --screen CONTROLLER`.
   Сам `appready` не доказывает загрузку контента.

При обновлении сначала останови старый мост командой `stop` прежней версии CLI,
затем обнови клон, собери CLI и выполни `start`.
Выполни `install-url`, замени существующую ссылку Lampa Remote на `data.url`,
затем явно перезапусти Lampa и повтори status/doctor. Вторую регистрацию не добавляй.
Плагин 0.2.x и protocol 1 с этой версией несовместимы; старый loader больше не используется.
Старое поле token в config.json читается для совместимости, но игнорируется;
после остановки старого моста его можно убрать. Остальные параметры и права сохраняй.
Удаление: останови мост и убери регистрацию плагина из Lampa; данные приложения не сбрасывай.

### Установить сам скилл

Копируй весь каталог `skills/lampa-remote`, включая `references/` и `agents/`,
в `.agents/skills/lampa-remote` выбранного проекта.
В новой сессии Codex скилл доступен по `$lampa-remote` и может выбираться по задаче.
Остальные хосты Agent Skills используют собственный каталог установки.
Клон утилиты, Node.js и ADB — отдельные предусловия: копирование скилла их не устанавливает.

## Читать и управлять

| Команда | Назначение и условия |
|---|---|
| `--help`, `--version` | Локальная справка; конфиг и TV не нужны |
| `start [SERIAL]` | Запуск моста; явный SERIAL также устанавливает reverse |
| `bridge` | Запуск/чтение состояния моста: PID, ready, active, idle |
| `stop` | Выключение моста, приложение остаётся запущенным |
| `app start`, `app stop`, `app restart` | Явное управление Android-приложением через ADB, без JS-подключения |
| `install-url` | Публичная ссылка самостоятельного плагина в JSON `data.url` |
| `doctor` | Пассивная проверка ADB, foreground, моста, плагина и протокола |
| `status` | Версии, appready, controller, компонент, заставка, visibility |
| `ui [--full] [--limit N] [--text TEXT \| --key KEY \| --section SECTION]` | Видимые доступные элементы, фокус, ID и счётчики |
| `action ID` либо `action --text TEXT / --key KEY / --section SECTION` | Действие по одной уникальной видимой цели |
| `key up/down/left/right/enter/back/long` | Навигация текущего controller; активная заставка сначала поглощает клавишу |
| `input [TEXT]` | Чтение/запись одного открытого несекретного поля; ввод не отправляет Enter |
| `settings open [SECTION]` | Открыть настройки или раздел, например `interface` |
| `settings get KEY` | Прочитать поддерживаемое простое несекретное значение |
| `settings set KEY true/false` | Установить видимый boolean-параметр; другой тип не поддержан |
| `player` | Диагностика DOM video; внешнего Android-плеера здесь нет |
| `logs [--follow]` | Буфер диагностики; follow выдаёт JSONL, удерживает мост; Ctrl+C — exit 130 |

`ui` по умолчанию возвращает до 50 элементов, `--full` — до 150 и bounds/полный status.
`settings open` сначала штатно закрывает открытую панель расширений, чтобы она
не перекрывала настройки и не оставляла controller другого экрана.
Явный `--limit` принимает 1..150. Допустим один фильтр:
text — подстрока, key/section — точное совпадение.
`totalVisible`, `matchedVisible`, `returned`, `truncated` показывают полноту выборки.
Это видимая область, не весь каталог контента.

У `action` text/key/section совпадают точно; поиск проверяет всех видимых кандидатов
независимо от лимита последнего UI-ответа.
Ноль совпадений — `TARGET_NOT_FOUND`, несколько — `AMBIGUOUS_TARGET`, без нажатия.
ID проверяет текущие element/controller/label/key/section и может стать `STALE_TARGET`.

### Дождаться условия

Выбери одно условие и ограничь ожидание:

```sh
node dist/cli.js wait --screen settings_component --timeout 3000
node dist/cli.js wait --key background --timeout 3000
node dist/cli.js wait --text 'Язык' --timeout 3000
node dist/cli.js wait --setting background --value true --timeout 3000
```

Поддержаны также `--section SECTION` и JSON-примитивы в `--value`: string, number, boolean, null.
`--screen` означает текущий controller, а не лежащий под диалогом компонент или старый settingsSection.
Текст — наличие подстроки хотя бы в одной видимой цели; неоднозначность здесь допустима.
`--timeout` — 1..60000 мс, по умолчанию `rpcTimeoutMs`.
Ожидание делает короткие чтения на компьютере, не блокируя очередь плагина до истечения всего timeout.
Setup/wake происходит до цикла; внутри цикла нет повторов мутации или произвольного JS eval.

### Подтвердить изменение

Перед изменением настройки прочитай исходное значение.
Для boolean предпочитай `settings set KEY true/false` после открытия нужного раздела:
в отличие от toggle-действия, желаемое значение задано явно.
Проверь `settings get`, при необходимости выйди и открой раздел снова для проверки сохранения.
При пробе восстанови значение и повтори проверку.

Для ввода открой требуемое поле, прочитай `input`, затем передай текст одним аргументом.
Ответ разделяет `domWritten`, `appConfirmed` и доступное `appText`.
`appConfirmed: false` означает расхождение с зеркалом Lampa,
`null` — независимое подтверждение недоступно.
Не называй такую запись принятой приложением.
Секретные поля отклоняются; не обходи отказ через ADB input/eval.

## Настроить приватный конфиг

Конфиг создаётся первым рабочим вызовом в `.local/config.json` у клона.
`LAMPA_REMOTE_STATE` меняет весь каталог состояния.
Файл должен быть 0600, каталог — 0700. Транспортный токен не создаётся.
`doctor` не создаёт отсутствующий конфиг.

| Поле | Дефолт | Значение |
|---|---|---|
| `port` | 18657 | Порт loopback-моста; 1..65535 |
| `serial` | null | Конкретный ADB serial или единственное подключённое устройство |
| `idleTimeoutMs` | 3600000 | Простой после завершения активных CLI/RPC; 1..604800000 мс |
| `rpcTimeoutMs` | 5000 | Ответ одной RPC; 1..60000 мс |
| `adbTimeoutMs` | 10000 | Одна ADB-команда; 1..60000 мс |
| `wakeTimeoutMs` | 20000 | Общий бюджет подключения; 1..60000 мс |
| `wakeRetryIntervalMs` | 1000 | Интервал служебных импульсов при активном CLI; 1..60000 мс |
| `appPackage` | ru.twicker.lampa | Android-пакет установленной Lampa |
| `appActivity` | .ui.MainActivity | Её стартовая Activity |
| `androidWakeCode` | KEYCODE_F8 | Служебная Android-клавиша |
| `browserWakeCode` | 119 | Соответствующий код keydown/keyup в WebView |
| `appOrigin` | http://lampa.mx | Точный разрешённый Origin WebSocket; http(s) без пути/credentials |

Редактируй JSON атомарной заменой с сохранением остальных полей и прав доступа.
Неизвестные поля и неверные типы дают `CONFIG_INVALID`, конфиг не сбрасывается.
После правки перезапусти мост через `stop`/`start`.
После смены port/browserWakeCode/wakeTimeoutMs повтори `install-url`, замени URL на TV
и перезагрузи плагин. Остальные тайм-ауты и idle не требуют смены ссылки.

Мост слушает только loopback. HTTP API принимает локальные небраузерные запросы;
браузерный Origin/Fetch-Site и чужой Host отклоняются. WebSocket принимает только
настроенный appOrigin. Это защита от посторонних веб-страниц, а не авторизация
локальных программ: процессы Mac и TV через ADB reverse имеют доступ без токена.
Не публикуй порт моста в LAN или интернете.

Тёплый совместимый плагин обслуживает RPC без ADB на каждый вызов.
При отсутствии подключения CLI проверяет foreground и reverse, затем шлёт ограниченные служебные импульсы.
Каждый импульс снова проверяет foreground; фактическая RPC отправляется один раз после handshake.
Плагин поглощает служебные keydown/keyup и не делает reconnect polling после отключения.
CLI lease, RPC и `logs --follow` удерживают мост; плагиновые события/heartbeat не продлевают idle.

## Разобрать ответ или ошибку

Успех: `{"ok":true,"data":{},"meta":{}}` в stdout.
Ошибка: `{"ok":false,"error":{"code":"CODE","message":"…","hint":"…"}}` в stderr.
`meta` и `hint` необязательны. Для мутации с неизвестным исходом присутствует `error.outcome: "unknown"`.
Help/version — текст; `logs --follow` — последовательность JSON-объектов по строкам.

| Exit | Смысл |
|---|---|
| 0 | Успех |
| 1 | Непредвиденная ошибка |
| 2 | Ошибка аргументов |
| 3 | Не выполнено условие/недоступна цель/отказ плагина; WAIT_TIMEOUT |
| 4 | Транспорт/тайм-аут; отдельно проверяй outcome |
| 130 | Прерванный пользователем logs --follow |

- `CONFIG_MISSING/INVALID/PERMISSIONS`: исправь путь/JSON/права, сохрани параметры; не удаляй конфиг для обхода.
- `ADB_NO_DEVICE/NOT_READY/AMBIGUOUS/NOT_FOUND`: проверь ADB и подтверждённый serial, подключение и авторизацию.
- `APP_NOT_FOREGROUND/APP_HIDDEN`: обычная команда не открывает приложение; используй явный app start при разрешённом запуске.
- `APP_NOT_READY`: плагин доступен, но Lampa ещё загружается; RPC не отправлена.
  Дождись завершения загрузки и повтори команду. Перезапуск и переустановка плагина не нужны.
- `BRIDGE_UNAVAILABLE` в doctor: мост выключен; пассивная диагностика не включает его. Рабочая команда или start включит.
- `PROTOCOL_MISMATCH`: обнови согласованную пару host/plugin, пересобери CLI и перезагрузи плагин.
- `PLUGIN_WAKE_TIMEOUT/TV_DISCONNECTED/TV_TIMEOUT`: проверь foreground/ADB/reverse и загрузку плагина; исход мутации выясняй чтением.
- `STALE_TARGET/TARGET_NOT_FOUND/AMBIGUOUS_TARGET`: перечитай UI и уточни цель. Выбор первого совпадения не разрешён.
- `DIALOG_ACTIVE` при `settings open`: поверх расширений открыт диалог; закрой его через `key back`, перечитай UI и повтори переход.
- `SCREENSAVER_ACTIVE`: читай состояние пассивно; для порученного управления отправь одну явную key, затем перечитай UI.
- `WAIT_TIMEOUT`: условие наблюдалось как невыполненное; это не неизвестный исход мутации.
  `WAIT_READ_TIMEOUT/WAIT_READ_FAILED` означают сбой чтения, не доказательство отсутствия цели.
- `NO_UNIQUE_EDITABLE_FIELD`: открой нужное поле и проверь фокус; `SENSITIVE_INPUT_REFUSED` сохраняет границу секретных полей.

После timeout/обрыва читай состояние до повтора действия, даже если ошибка не содержит outcome.
Снимок после dispatch подтверждает отправку и доступный DOM, а завершение задачи — отдельное наблюдение.
