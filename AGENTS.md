# Разработка Lampa Remote

Эти правила предназначены для мейнтейнеров и агентов, меняющих репозиторий.
Установка и управление TV описаны в [скилле](skills/lampa-remote/SKILL.md).

## Проверяйте изменение перед коммитом

```sh
npm ci
npm run typecheck
npm test
```

`npm test` собирает CLI и запускает `node:test`.
Для одной регрессии после сборки:
`node --test --test-name-pattern='имя теста' tests/agent-commands.test.mjs`.
Отдельного линтера в проекте нет.

## Сохраняйте границы модулей

- `host/` — TypeScript: CLI, мост, протокол, ADB и состояние компьютера.
- `plugin/remote.js` — JavaScript для WebView Lampa; Node.js API здесь недоступны.
- `tests/` — loopback HTTP/WS, fake ADB и настоящий плагин в VM.

Исправляйте причину в общем пути, проверив его callers.
Добавляйте зависимость или слой только для задачи, которую существующий код не решает.
Сохраняйте принятые соглашения; рефакторинг ограничивайте затронутым поведением.
Комментарии объясняют причину решения, а не историю правки.

## Сохраняйте контракты CLI и плагина

- JSON-успех идёт в stdout, JSON-ошибка — в stderr; коды завершения остаются стабильными.
- Обычная команда не запускает и не выводит Lampa на передний план.
  Для этого существуют только явные `app start|stop|restart`.
- Плагин ждёт служебную клавишу без фоновых попыток подключения.
  Idle считается после завершения активных CLI/RPC; события плагина его не продлевают.
- Мутация с неизвестным исходом не повторяется автоматически.
  TTL использует локальное монотонное время, а не разность часов TV и компьютера.
- Действие требует уникальной видимой цели; лимит UI-вывода не ограничивает поиск неоднозначности.
  Запись в DOM не подтверждает принятие ввода приложением.
- После смены протокола или исходника плагина проверяйте совместимость пары host/plugin.

## Проверяйте поведение на подходящем уровне

Для дефекта добавляйте регрессию в существующий набор у соответствующей границы.
Сетевые контракты проверяйте реальным loopback, ADB — поддельным процессом, плагин — через VM.
Не ослабляйте assertion ради зелёного прогона.
Живой TV используйте по поручению пользователя; сохраняйте исходные настройки и восстанавливайте их после пробы.
Тесты VM не подтверждают доставку клавиш, кэш WebView или фактический ввод на TV.

При изменении команд, конфига или установки обновляйте README и операционный справочник скилла.
Меняя инструкции скилла, проверяйте его переносимость и поведение на установке, ошибке и соседней задаче.
Новые замеры сопровождайте сетапом, выборкой и методом; синтетические числа не заменяют замер на TV.

`.local/`, токены, URL установки и данные пользователя остаются вне Git и диагностического вывода.
В тестах используйте фиктивные секреты. Перед публикацией проверьте также историю Git.
